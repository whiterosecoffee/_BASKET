# Full-conversation recovery and purpose explosion — reusable research method

**Status:** documented procedure; native raw transcript, uploaded media and browser widget state were NOT directly exported during this capture.

## Input contract
- Conversation identity/reference if exposed, native transcript export and attachments if available, and complete visible turn history as provisional fallback.
- Live _BASKET and _PATTERNS root guidance/index/receipts, issue/PR changed-file inventories and exact Git commits.
- Evidence classes: USER_DIRECTIVE, CONVERSATION_RESULT, REPOSITORY_VERIFIED, EXTERNAL_RESEARCH, INFERENCE, UNKNOWN.
- Source timestamps or turn order; uncertainty where conversation slices or screen widgets are missing.
- Authority: archive only within allocated path, no data-store duplication or automated cross-branch mutation.

## Algorithm: seven evidence-gated stages

**1. Source acquisition, not summarization.** If a real ChatGPT conversation export is accessible, ingest it as read-only data, preserve message IDs, ordering, roles, attachments and content-block types. Include code, tables, prompts, references, corrections, hidden? Never claim model private reasoning or inaccessible widget payload. If no export API exists, disclose coverage as PARTIAL_SOURCE_COVERAGE and use accessible conversation plus repository evidence instead. Do not invent quotations for missing turns.

**2. Enumerate content units.** Extract requests, constraints, decisions, revised decisions, examples, mathematical formulas, calculations, UI elements, tested artifacts, error reports, tool calls/results, sources, alternative approaches, rejected ideas, accepted evidence and open commitments. Preserve the original passage reference for each. Record whether an artifact was authored, committed, tested, merged or deployed.

**3. Purpose clustering / explosion.** Cluster by independently testable input/output contracts, not by every rhetorical topic. For this session the minimum distinct capabilities are P01 historical state, P02 range visual UI, P03 source custody, P04 historical outcomes and P05 architectural reuse. Only create a new active node/branch after confirming its independent ownership and acceptance; otherwise keep a planned addressable purpose record with a pointer to existing code.

**4. Artifact reconciliation.** For each unique unit, locate repository evidence at an exact SHA. Cross-check actual changed files (especially code vs documentation), source time/vintage, pipeline outputs, PR status and ownership. Mark transferred, linked, blocked or excluded with reason. Do not treat an inaccessible artifact as nonexistent.

**5. Comparative audit and recovery.** Reconstruct a decision timeline, note what changed after user corrections, and compare the saved handoff with source. Test information loss: important UI interaction missing, negative example omitted, formula semantics changed, status inflated, owner/destination omitted, or time-of-observation lost. Record restored knowledge units with why they matter. Score process and product separately; do not increase score merely because another file was made.

**6. Publish smallest durable package.** Create one clean preservation branch from current main under the authorized owner subtree. Include AGENTS.md, state.json, an index, purpose registry, feature designs, pinned source references, evidence/asset ledger and pickup guidance. Publish code only when actually absent and authorized. For existing projects, use links and manifests rather than copying mature code, licensed bars or media. Leave branch unmerged, editor unclaimed; optional draft PR gives discoverability.

**7. Verify and close.** Read back the exact committed branch and every new path; lint JSON, compare source SHA and PR changed paths, run applicable tests, distinguish generic CI from domain validation. Fresh future receiver verifies independent accessibility. If the native export was absent, do not say the chat was fully scraped; flag precise coverage gap. Archive decision considers source conversation preservation separately from continuing owner implementation.

## Microsoft engineering pattern
- Use deterministic parsers, inventory/diff/validator functions for source facts and extraction integrity.
- Use agents selectively for semantic clustering, ambiguities, causal explanation and alternative design comparison.
- Prefer a short explicit workflow over more agents: Acquire → Enumerate → Classify → Verify → Preserve → Audit → Hand off.
- Keep source/review decisions with durable checkpoint IDs and commit pins; a checkpoint does not replace the source dataset.
- Human-in-the-loop is for changing owner scope, merging/releasing or approving disputed canonical contracts, not routine read-only extraction.
- Trace each claim to a source revision; avoid excessive copies of raw private conversations or provider-licensed market data.

## Completeness / falsification tests
T1: Every original user request from available source has a disposition.
T2: Every visible UI/media output has a retrievable artifact or an explicit NOT_EXPORTED gap.
T3: Each distinct formula, window, unit and denominator retains semantics.
T4: Every error and correction has current evidence and an owner acceptance criterion.
T5: Every independent capability maps to one current owner, no duplicate code.
T6: Every recipient can open the captured AGENTS, state, source pins and needed tests.
T7: No synthetic/retrospective result is upgraded to a current, calibrated or deployed claim.
T8: Receiver independently acknowledges only after fresh readback, not based on sender's own proof.

## Return contract
Return: source coverage (including missing assets), purpose IDs, exact evidence pointers, published branch and commit, authoring scope, test/CI status, unique new insights, unresolved owner decisions, and one retrieval-first next action. Do not claim background execution or automatically split into five branches. A true full transcript fidelity certificate requires the original export and a deterministic message/asset inventory comparison.
