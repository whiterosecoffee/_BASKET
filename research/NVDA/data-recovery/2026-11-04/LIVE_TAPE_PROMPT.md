# Live-tape analysis prompt v1

Use the following instructions as the operator prompt. Example invocation: “Analyze live tape for NVDA, regular session, as of now. Use SMH, QQQ and SPY as comparators.” Defaults are the latest three completed five-minute windows, an optional current partial window, and the preceding 15 minutes of trade detail. Expand the lookback only to answer the request or resolve a missing comparison.

## Mission and system boundaries

Explain where trading is concentrated, which direction takes fewer shares per dollar, whether participation is unusual, and whether price actually holds a new range. Start with session status and a timestamp. Separate observed facts, inferences and conditional scenarios. Report in USD and display America/Chicago time; preserve UTC timestamps and America/New_York exchange dates in records.

For _BASKET repository work, read the current main [AGENTS.md](../../../../AGENTS.md), [worker protocol](../../../../orchestration/WORKER_PROTOCOL.md), [spark registry](../../../../orchestration/sparks.json), and [version policy](../../../../architecture/VERSIONING.md). Follow the existing resolver, source adapters, schema, versioning and branch ownership. B02 owns canonical ingestion and data, B06 owns traversal, and B01 owns independent validation. Use the existing daily journals and the B02-approved write path. This research prompt and CLI are the operator layer. Route canonical changes through [B06 handoff #204](https://github.com/whiterosecoffee/_BASKET/issues/204) and the relevant owner. Keep licensed raw data and user screenshots out of Git.

## 1. Read local first, backfill with Massive, always persist new evidence

1. Fix an explicit as-of cutoff and exchange session. Discover the approved local date JSONL for the ticker and each requested comparator through the current resolver or known workspace path, such as `_DATA/NVDA/YYYY-MM-DD.1m.jsonl`. Verify symbol, session date, source, schema, adjustment basis, timestamp coverage and point-in-time availability. A file existing is insufficient evidence of coverage. Detect gaps in the requested interval and the prior close needed for return calculations. Check exchange calendar, daylight saving, auction boundaries, halts and early closes. Do not fill unknown minutes with zeros.
2. Reuse eligible local observations. If current data or required coverage is missing, use the **Massive connector** to fetch only the necessary missing or explicitly requested revision interval. Request unadjusted minute aggregates for bar metrics and SIP trades for executed volume by price. Match all comparator cutoffs. Follow every cursor for trade or quote requests, recording requested half-open intervals, source, timestamp basis, completion and page count. Do not substitute VWAP or OHLC for executed price bins. Fetch quote data only if requested or needed to distinguish trade direction and the entitlement supports it.
3. **Write every newly queried market observation needed for this analysis back to the appropriate local date-specific JSONL using the existing authorized writer, before calling the refresh complete.** This applies to every ticker queried and each supported data class. Keep bars, trades, quotes, and derived price-bin evidence in their designated daily partitions or existing evidence schemas. Never insert a trade or quote into a bar journal. If the connector only exposes an aggregated result, persist that result as derived evidence through the approved evidence route and label raw-row persistence unavailable. Never claim that raw data was saved from an aggregation alone.
4. Preserve provider identity, original units, source IDs, observed/available/ingested timestamps, session date and data basis. Append unseen identities, skip exact repeats, and use explicit superseding revisions for conflicting authoritative updates under the existing contract. Use the current writer's locking and retry semantics. Keep one exchange date per file and verify replay through the cutoff, rows added/revised/unchanged, and gaps remaining. If the expected writer or schema is unavailable, use only an approved recoverable staging path, report precisely what was staged and what remains unwritten, and route unresolved canonical writes to B02. Do not overwrite, invent a canonical store, or commit provider rows to Git.
5. Keep historical as-of replay strict. Exclude observations first available or ingested after the replay cutoff under the applicable contract. A later backfill may repair today's journal but does not establish historical decision-time availability. Separate latest completed minute from provisional last trade and from the most recent completed five-minute block.

## 2. Measure the stock tape

- **Session context:** show last price/time/source, regular-session high/low, prior official close if verified, and session-to-date shares. Keep premarket, regular and after-hours volumes distinct. Compare same-clock cumulative participation with a median of 20 eligible prior sessions where available. Report comparator count and missing history. A single prior day is a named fallback comparison, not a typical-volume baseline.
- **Window metrics:** use clock-aligned completed five-minute blocks. Also show completed 15-minute high, peak minute and shares when requested. Compute close-to-close net USD change from the preceding minute close, signed USD/min, signed USD per million shares, and shares per absolute dollar for material moves. At the opening boundary use the first eligible open and flag auction exposure. The research CLI uses an uncalibrated 5 bp near-flat floor. Report its method/version and do not mix auction windows with ordinary windows. Show sampled path coherence where available so a flat close after a round trip is distinguishable from quiet trading.
- **Directional pair:** compare the latest eligible completed window with its nearest opposite-direction eligible window in the same session within six five-minute slots, as in the current CLI. Report both times and costs, and which direction moved more easily. Leave an unavailable comparison blank with a reason. An ease flip is separate from acceptance of a new price range. Partial windows may be described but never confirm shifts or ease flips.
- **Volume at price:** for fully paginated, eligible stock prints, sum fractional sizes where supplied in fixed `[low, high)` $0.25 NVDA bins. Show busiest bin and shares, adjacent pocket with exact boundaries, and comparison to prior windows. Keep reported trade sums separate from bar totals. Flag isolated off-range prints or special conditions, state the filter, and never let an outlier stretch the range. For another ticker document the bin configuration before comparison.
- **Range decision:** freeze the active band before checking it. One completed five-minute close beyond an edge is a probe. Confirm a shift with a second consecutive close outside the same edge or a fully paginated modal bin beyond that edge in the same direction. With bars alone, require two closes and label the result bar-only. Record old/new bands, confirmation time and evidence. For a reversal candidate, require a countertrend move, a defended retest, then a break of the prior swing. State the level that invalidates it.
- **Market overlay:** compare the ticker against SMH, QQQ and SPY on identical timestamps. Distinguish nearly flat net returns from actual range compression, and broad weakness from ticker divergence. Show return, high-low width and participation only where coverage is comparable.
- **Options overlay:** if supplied or entitled, timestamp HIRO and compare its change over matched windows with stock price response. Keep cumulative HIRO, modeled GEX by strike and expiry, published OI, and options trade volume separate. Avoid inferring a pin from a label or net GEX alone. Treat passive absorption as a hypothesis unless contemporaneous trade/quote evidence supports the aggressor classification and depth behavior. Never assign buyer identity from public prints.

## 3. Report and verify

Lead with `session · CT as-of · price · active range/state · easier direction · session shares`. Then show a compact table with window, range, close, bar shares, shares in range, modal bin, signed USD per million shares, and state. Add one market-overlay sentence, a separate options sentence when relevant, and a concrete next trigger plus invalidation. Use ranked conditional scenarios when requested. Quantitative probabilities require a documented out-of-sample evaluation.

Include source, last complete minute, evidence class, journal paths, import counts, unresolved gaps, method version and replay cutoff. For an audit or formal run retain input digests and exact tool commit/configuration. Never infer a deploy, canonical integration, or passing independent checks from a local replay.

## NVDA worked example — Nov. 6, 2026

At 11:15 CT the minute journal showed **$188.08** and **82.26M** regular-session shares. In 11:05–11:10, **817K** SIP shares traded at **$188.25–<$188.75** and the modal bin was **$188.50–<$188.75**. In 11:10–11:15 that range had **615K** shares and the mode moved to **$188.25–<$188.50**. The 11:15 close was below $188.25 while the mode stayed inside, so label it **probe**. At 11:20 a second completed close below the edge confirmed a **bar-supported downshift**. This transition does not require a lower trade mode. The tape matrix comparison at 11:15 was approximately **2.34M shares/$ up** versus **2.53M shares/$ down**, an ease comparison that did not overturn the range evidence.

Use [the battle-range runbook](BATTLE_RANGE_RUNBOOK.md) for detailed policy and prior art. Run [tape_matrix.py](tape_matrix.py) against the journal for bar metrics. The current research CLI is read-only and assumes standard regular hours. Fetch, writes, trade bins, nonstandard sessions and the canonical integration are handled separately under the system ownership rules.
