## Retained upgrade and efficiency proposals

- Identify current assignment: analyze, plan, revise or invoke closeout.
- Define requested outcome -> artifact/action -> completion evidence.
- Deliver the actual requested artifact instead of transferring its production.
- Require a real transfer reason: authority/access/evidence/ownership/dependency
  or the user's explicit stopping point.
- Scale depth to materiality: losing an item would change a decision, authorized
  action, acceptance judgment, recovery method or reproducibility.
- Treat retrospective improvements outside the current objective as optional.
- Verify stored content, destination and revision after writing.
- Give repeated requirements canonical IDs; preserve distinct constraints.
- Decompose progressively by ownership, contract or dependency, not mention count.
- Select specialist reviews rather than running all roles by default.
- Use bounded evidence packets without removing context needed for sound review.
- Keep one shared index, one reconciler and one final handoff.
- Use sequential specialist roles where delegation is unavailable.
- Avoid branch/workspace creation for read-only review unless local governance
  explicitly requires it.
- Reuse current contracts; do not create a competing scheduler, registry or queue.

## Positive and negative lessons

L1 — Preserve causal knowledge.
Observation: earlier handoff formatting lost material supplied information.
Mechanism: preserve observation, rationale, method, limits and destination together.
Repeat: source inventory -> standalone artifact -> loss/actionability check.
Boundary: formatter regression success does not prove complete semantic extraction.
Destination: existing #169/#178 artifacts; retained here as comparison knowledge.

L2 — Use exact revisions and readback.
Observation: stale completion/CI claims and temporary staging complicated recovery.
Mechanism: bind evidence to an exact source and verify durable publication.
Repeat: refresh head, identify actual checks, persist, fetch back and compare.
Boundary: readback verifies bytes, not policy correctness or downstream value.

L3 — A handoff can replace the task accidentally.
Observed path: recommendations, amendments and another handoff replaced a complete
requested revision.
Consequence: user had to ask again.
Better path: identify task mode and deliver concrete requested language.
Prevention: explicit artifact acceptance and a justified-transfer gate.

L4 — Discover before designing.
Observed path: proposed new modular review work before finding PR171, PR177,
PR179 and the existing component/loop efforts.
Better path: inspect relevant sources and owners before introducing structure.
Boundary: discovery should be bounded by decision value, not exhaustive rereading.

L5 — Temporary staging is not persistence.
Observed path: large drafts lived in session storage and were lost on interruption.
Consequence: repeated reconstruction without repository delivery.
Better path: durable local files, small real publication checkpoint, exact readback.
Applied recovery: this continuation verified README commit c1601f36ea22ea4785ab2a32903faa7c7d0cda3d
before expanding the archive.
Boundary: the cause of earlier interrupted connector calls was not established.

L6 — Bound retries.
Observed path: repeated branch/tree calls ended without confirmed effects.
Better path: inspect remote state before retry; avoid concurrent duplicate mutation;
change available transport or report a precise blocker.
Acceptance: no false push claim and no duplicated effect.

L7 — Length and scores are weak proxies.
Observation: several revisions and self-scores existed without candidate trials.
Better path: fixed expected outcomes, receiver execution and measured usage.
Boundary: static review still helps find contradictions, but is not behavioral proof.

Storage: these lessons are material archive content. Adoption and observed benefit
remain distinct.
