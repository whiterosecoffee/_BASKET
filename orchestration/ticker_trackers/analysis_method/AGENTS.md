# Company analysis method — standing guidance

This is a draft reusable capability inside the existing ticker-tracker composition scope, not a promoted global pattern, executable controller or replacement financial engine.

Read repository AGENTS.md, this state.json, feature-design.md and review.md. Then read only the selected ticker's AGENTS.md/state.json and the inputs needed for the current action. A child references this method and records only differences. JSON pointers do not execute inheritance: the agent reads and interprets them. Explicit user instructions take precedence; unresolved ownership or accounting conflicts are recorded.

Role: connect evidence -> business economics -> recurring diluted earnings and distributable cash -> conditional valuation -> falsifiable watch plan. Keep descriptive tape separate from fundamental value. Prefer the smallest useful delta to an existing analysis. Do not generate a new ingestion service, canonical relationship store, financial engine or scheduler.

Inputs: dated sources with claim class/period/availability; security and fiscal calendar; business lines; partner roles; reported and adjusted earnings reconciliation; capital obligations; assumptions; accepted provider receipts for market work. Outputs: report, contextual input manifest, source ledger, state with missingness/next action, reproducible arithmetic and review evidence.

Never relabel guidance as consensus, a model as guidance, a product announcement as revenue, a pricing promise as executed terms, backlog as profit, raised funds as earned cash, or an annual EPS multiple as NTM. Future GAAP EPS remains null unless reconciled. Do not assume all excluded stock compensation is non-economic. Never subtract the same financing, depreciation or lease cost twice.

Use existing owner contracts for provider data, events, relationships, models and traversal. Store provider queries in the approved durable data plane as one-session-date JSONL; research source observations are not a replacement. Private account/holdings data is excluded from GitHub. Shared method changes need versioning and second-ticker comparative review before promotion.

Selection: follow child state's first unmet objective whose inputs and ownership are available; otherwise perform independent source validation or write an owner handoff. Record completed actions only after verifying artifacts/receipts. Always report branch-vs-main, historical-vs-current, manual-vs-operational and independent-review status.
