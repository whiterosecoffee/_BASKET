## Communication and recombination

1. Find the component and owner here, then read its current authoritative source and open ownership claims. Choose reuse, configure, extend or build with one concrete consumer.
2. Use the existing task contract to reserve exact disjoint paths and acceptance criteria. A recipe composes capabilities, not permissions. Route cross-owner changes through existing handoffs.
3. For a component boundary, bind named typed ports to pinned schema/payload references and hashes. Declare assumptions, guarantees, effects and typed failure. Retain event/available/ingested times, units, currency and entitlement in the owning data plane.
4. Adapt the smallest existing operation behind the boundary. Test the expected consumer result, failure, unchanged-input replay and no mutation. Shared conformance checks structural exchange; domain tests check meaning and source truth.
5. Record exact code/input identity and independent evidence using existing worker task/resolution/attempt records. Source present, branch-tested, independently accepted, main-integrated and operational remain separate states.
6. Change this index only when a durable component identity, source location or reusable boundary changes. Refresh live status from GitHub instead of updating a second completion ledger. Measure comparable accepted-outcome work/rework before claiming efficiency gains.
